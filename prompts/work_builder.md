# Work Skill Builder

## Task

Generate `work.md` from the Work Skill analysis.

The file must be executable: it should let the generated Skill perform work in this person's style and domain, not merely describe them.

## Template

```markdown
# {name} - Work Skill

## Scope

{owned systems, modules, products, domains, and responsibility boundaries}

## Technical or Professional Standards

{standards, stack, naming rules, quality bars, review rules, design rules, or role-specific methods}

## Workflow

{task intake, design process, execution steps, review process, incident or exception handling}

## Output Preferences

{preferred document structure, code examples, tables, message style, report format}

## Knowledge Base

{explicit lessons, pitfalls, domain facts, reusable heuristics, and evidence-backed judgments}

## Evidence Gaps

{dimensions with insufficient source material and what to add next}
```

## Rules

- Write in English.
- Keep commands, paths, API endpoints, field names, and code examples exact.
- Do not include unverifiable claims.
- Use specific operational guidance instead of personality labels.
- If evidence is weak, put the item under `Evidence Gaps` rather than inventing details.
